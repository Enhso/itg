# Synthetic data generation boundary

The product ships synthetic football events only. Clubs, players, match outcomes, events, tactical shifts, and ground truth are generated by the repository's deterministic match engine.

## Calibration policy

During development, StatsBomb Open Data may be inspected temporarily to learn football-event semantics and broad aggregate targets. It is not a runtime dependency and no raw files, real match records, real names, or copied fixtures may be committed or included in the deployed product. Any downloaded source belongs in an external scratch location and must be removed after calibration.

Calibration retains only derived, reviewable targets such as broad event-count bands, outcome relationships, and phase-of-match tendencies. The generator remains seedable and controllable so the scripted planted-shift story can be reproduced and independently evaluated.

For the first calibration pass, ten event files from the official open-data
repository were inspected outside the repository. The sample's mean count of
core action events (passes, carries, pressures, and shots) was about 2,275 per
90-minute match, with roughly 27 such events per minute. The generator's
default event volume is therefore 27 events per minute; its extra planted-shift
events intentionally make the tactical change observable rather than trying to
replay any source match.

The calibration now fits a compact Markov model from a larger temporary sample
(`scripts/fit_statsbomb_model.py --matches 120`). It retains only aggregate
state transitions and displacement distributions in
`data/models/statsbomb_markov.json`; raw source files are not retained. The
generator uses those parameters to correlate each team's next event type and
location with its previous event, while preserving the planted-shift controls.
No source match teams, players, outcomes, coordinates, or event rows are
fixtures for this product.

Coordinates use StatsBomb's native `120x80` pitch throughout the deterministic
pipeline. A separate bounded 360 calibration
(`scripts/fit_statsbomb_360.py --matches 32 --workers 8`) retains only
event-centered spatial summaries in `data/models/statsbomb_360_templates.json`.
The 360 source is used as sparse scene calibration, not as continuous tracking
or shipped match data.

The renderer uses those 360-derived summaries to place a fictional,
role-aware 22-player scene around the active event. It does not copy source
players or claim that event-centered 360 freeze frames are continuous tracks;
movement between frames is deterministic interpolation/noise around the
synthetic formation, with smooth bounded motion rather than frame-by-frame
random sampling.

To repeat the calibration from a clean checkout, run
`uv run python scripts/fit_statsbomb_model.py --matches 120`. The script reads
the official repository over HTTPS and writes only the aggregate parameter
artifact.

Before using the source, verify its current license and attribution requirements. If the source is mentioned in a public write-up, include the required attribution without redistributing the source data. The product's runtime and demo captures remain explicitly synthetic.

## First vertical slice

The current deterministic slice provides:

- typed fictional event, match, and planted-shift contracts;
- reproducible JSONL event generation from a seed;
- an observable away-team high-press injection;
- four observable tactical shift profiles: high press, possession surge,
  direct attack, and low block;
- five-minute rolling pressure, field-tilt, possession, and pass-accuracy evidence;
- a thresholded moment detector with before/after windows;
- scoring against `ground_truth` with a configurable minute tolerance.

The next stages can consume `WindowStats.evidence()` and `DetectionResult` without recomputing statistics in an agent.

## Committed examples

`data/examples/` contains ten reproducible fictional matches. Each match has a
JSONL event stream and a paired `ground_truth.json` file. Regenerate them with:

```bash
uv run python scripts/generate_examples.py
```

The default seeds and shift settings deliberately vary the planted shift
between 61' and 62' and alternate the team, while preserving the scripted
high-press story.

## Synthetic footage

The deterministic renderer can turn the event stream into a small, fictional
MP4 clip:

```bash
uv run python scripts/generate_footage.py
```

This creates `data/examples/example-01.mp4` and a frame-to-event sidecar
manifest. It is intentionally simple broadcast-style footage: the JSONL
events and ground truth remain authoritative, while the clip provides a visual
surface for the later video-analysis stage.

Foundry video generation is an optional experiment:

```bash
export FOUNDRY_OPENAI_ENDPOINT="https://<resource>.openai.azure.com"
export FOUNDRY_VIDEO_MODEL="<video-deployment>"
uv run python scripts/foundry_video.py
```

The script uses `AzureCliCredential` indirectly through `az account
get-access-token`; it stores no keys. A video deployment must be available in
the resource and region. Generated-model footage must be labeled synthetic and
must not replace deterministic match state.
